# Verification Checklist

Mandatory V3 gate: open the latest local `docs/ARCHIVE-QUALITY-V3.md`; when formal archives exist, preserve a private rollback checkpoint and verify the relevant formal library hash baseline. A new clone with no formal archives must not depend on another machine's ignored private backup. Quality must come from `quality-gate.js`, never caller-specific success strings. `candidate-report.js` is authoritative for dynamically verified resource counts; a QA pass must be bound to Manifest/HTML/Markdown digests. Interruption marker `.publish-state.json` blocks Reader with HTTP 503 until explicit reviewed recovery. A schema-1 source snapshot or missing media identity must not be certified from asset hashes alone. Do not publish any partial candidate without explicit permission.

Tests: `node scripts/verify-source-protection-regression.js`, `node scripts/verify-pending-media-reader.js`, `node scripts/verify-callout-collector.js`, `node scripts/verify-quality-gate.js`, `node scripts/verify-publish-transaction.js`, `node scripts/verify-source-fidelity.js`, `node scripts/verify-agent-capture.js`, `node scripts/verify-agent-resume.js`, Reader/Release regressions with keep-fixture environment and `node scripts/verify-fidelity-v3-baseline.js`.

For long originals, require a source-fidelity audit: stable repeated tail passes, per-Block results (rendered / empty_verified / unsupported_visible / failed), file attachment identity and download permission, and semantic preservation of headings/links/Prompts. Compare source revisions without silently merging changed content. Check archive.json.quality.verified independently of legacy status. Inaccessible Feishu file cards must keep filename and source Block with unresolved status. A 100-item bounded media candidate is NOT a complete article when additional media/attachments remain. Verify actual Reader at desktop and 390px and do not publish a partial candidate as complete. Confirm no Feishu loading-placeholder thumbnail was counted as media. For a mixed source/legacy-media preview, require SHA-256 of copied files and one-to-one stable record+kind mapping, and continue to report `unverified` until current-source bytes are independently verified.

Check AGENT_CAPTURE_RESULT and exit code; confirm expected document ID and manifest state. Require `scan.verifiedComplete=true` with stable repeated tail passes AND complete `scan.calloutCoverage` (nested Callout virtual placeholders must be reconstructed gap-free); a stable top-level Block count alone is insufficient. Validate nonempty Markdown, article.html, content-addressed media paths, SHA-256, no remote `src` for expected media, failed Sheets and unsupported attachments. Resume must reject text/Block/media relation changes and leave the source untouched; test recovery after a simulated interrupted file. Hard byte caps apply even after unknown-size consent. Re-check existing Explain source staleness separately.

For Explain, keep originals untouched. Follow current docs/EXPLAIN-WORKFLOW.md, chapters/manifest.json and source fingerprint. Validate full Prompt text, evidence links and continuous-page rendering. Shared Reader changes require the documented regression commands with FEISHU_NOTES_VERIFY_KEEP_FIXTURE=1; never run recursive fixture cleanup by default.

Do not auto-run --confirm-large, auto-refresh an incomplete article, delete abandoned locks or commit/push.
